W1 : Trace one Set press, hop by hop, from browser back to browser.
When We type 70 in the Target box and press Set, the browser sends a POST to
/api/setpoint with sp=70. Flask checks that it's a number, keeps it between 0
and 100 and sends back {"ok": true, "sp": 70.0}. That reply only
means that the server got it, not that the light moved. Then Flask publishes
sp:70 on bench/s01/cmd to the broker. The broker sends it to the node because
the node signed up for that topic. The node starts moving the light toward 70
and keeps publishing the new level on bench/s01/light every second. That goes
back through the broker to Flask, where on_message saves it in latest["pct"]
with the time. Then the page asks /api/light every 2 seconds, gets the dict
back as JSON and updates the number. So that's when we actually see it go up
to 70 in the browser.

W2 : Why does the latest dict exist? One sentence.
The node sends readings on its own timing and the browser asks on a different
timing, so latest is like a mailbox where MQTT drops off the newest value and
Flask can grab it right away instead of waiting for the next message.

W3 : How old can the number on the page be, in seconds, and why?
About 3 seconds at most. The node only publishes every 1 second, so the value
in latest can already be 1 second old when the page asks for it. Then the page
only refreshes every 2 seconds, so that number can stay on the screen for 2
more seconds. So 1 + 2 gives 3 seconds in the worst case. That's fine
for someone looking at the dashboard, but it would be too slow for a control
loop.
